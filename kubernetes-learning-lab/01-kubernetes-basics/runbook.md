# Core Components Project Runbook

## Goal

Deploy and extend the Tiny Bookshop application while observing the first twenty topics in the lesson path.

This runbook creates resources only in namespace `k8s-learning-basics`. It does not change an existing application.

Keep the [manifest reading guide](manifest-guide.md) open beside the runbook. It links to the detailed explanation of every file and the container commands inside it.

## Dependencies

- The requirements and safety checks in the project [README](../README.md) are complete.
- Your kubeconfig points to a non-production cluster you are allowed to use.
- Your account can list nodes and create Namespace, ResourceQuota, ConfigMap, Secret, Deployment, Service, DaemonSet, Job, and CronJob resources.
- Cluster nodes can pull `busybox:1.36`, or already have it cached.
- Local port `8080` is free.

Optional storage practice also requires permission to create StatefulSets and PersistentVolumeClaims plus a suitable default StorageClass. Optional ingress practice requires permission to create Ingress resources plus an existing compatible ingress controller.

If you cannot create namespaces, ask the cluster administrator for a practice namespace. The manifests must then be adjusted consistently before use.

## 1. Enter the project folder

From the repository root:

```console
cd kubernetes-learning-lab/01-kubernetes-basics
```

## 2. Confirm the cluster and view its shape

```console
kubectl config current-context
kubectl cluster-info
kubectl get nodes -o wide
```

Stop if the context is not the intended cluster.

`kubectl cluster-info` shows the API endpoint. `kubectl get nodes` shows the machines registered with the cluster. On a managed service, the provider may hide the control-plane machines; that is normal.

## 3. Create the namespace and quota

```console
kubectl apply -f manifests/00-namespace.yaml
kubectl apply -f manifests/05-resourcequota.yaml
kubectl get namespace k8s-learning-basics
kubectl -n k8s-learning-basics describe resourcequota learning-object-limits
```

Expected result: the namespace is `Active`, and the quota shows generous count limits with little or no usage.

## 4. Create external configuration

```console
kubectl apply -f manifests/10-configmap.yaml
kubectl apply -f manifests/11-secret.yaml
kubectl -n k8s-learning-basics get configmap hello-page
kubectl -n k8s-learning-basics get secret hello-settings
```

Expected result: both resources exist. The commands do not print the Secret's value.

The Secret contains practice-only values. Never commit a real password in plain YAML.

## 5. Create the application workload

```console
kubectl apply -f manifests/20-deployment.yaml
kubectl -n k8s-learning-basics rollout status deployment/hello-web --timeout=120s
```

Expected result: the rollout finishes successfully.

See the ownership chain:

```console
kubectl -n k8s-learning-basics get deployment,replicaset,pods -l app=hello-web -o wide
```

The Deployment creates a ReplicaSet, and the ReplicaSet keeps two Pods running. Generated ReplicaSet and Pod names contain changing suffixes.

## 6. Inspect Pods and their configuration

```console
kubectl -n k8s-learning-basics get pods -l app=hello-web -o wide
kubectl -n k8s-learning-basics describe deployment hello-web
kubectl -n k8s-learning-basics exec deployment/hello-web -- printenv APP_ENVIRONMENT
kubectl -n k8s-learning-basics exec deployment/hello-web -- printenv DEMO_USER
```

Expected values are `learning` and `learner`. They came from the ConfigMap and Secret references in the Deployment.

Inspect the page generated by the init container from the ConfigMap template:

```console
kubectl -n k8s-learning-basics exec deployment/hello-web -- head -n 8 /www/index.html
```

## 7. Create and use the Service

```console
kubectl apply -f manifests/30-service.yaml
kubectl -n k8s-learning-basics get service hello-web
kubectl -n k8s-learning-basics get endpointslice -l kubernetes.io/service-name=hello-web
```

The Service is a `ClusterIP`. Its EndpointSlice should contain the addresses of two ready Pods.

Test the in-cluster Service name from an application Pod:

```console
kubectl -n k8s-learning-basics exec deployment/hello-web -- wget -qO- http://hello-web
```

Then make it temporarily reachable from your computer. Keep this command running:

```console
kubectl -n k8s-learning-basics port-forward service/hello-web 8080:80
```

Open `http://localhost:8080` in a browser. You should see `Tiny Bookshop` and `Release 1.0`.

From a second Windows terminal, you can also run:

```console
curl.exe http://localhost:8080
```

On Linux or macOS, use `curl` instead of `curl.exe`. Press `Ctrl+C` in the first terminal when you want to stop port-forwarding.

## 8. Practise the essential `kubectl` actions

You have already used `apply`, `get`, `describe`, and `exec`. Use `logs` to read the web server output:

```console
kubectl -n k8s-learning-basics logs deployment/hello-web --tail=20
```

Use a label selector to narrow a result:

```console
kubectl -n k8s-learning-basics get pods -l app=hello-web
```

Demonstrate `delete` and reconciliation safely. Copy one generated Pod name from the result, then run:

```console
kubectl -n k8s-learning-basics delete pod PASTE_ONE_POD_NAME_HERE
kubectl -n k8s-learning-basics get pods -l app=hello-web --watch
```

The Deployment returns the actual count to two by creating a replacement Pod. When two Pods are ready, press `Ctrl+C`.

## 9. Inspect labels, selectors, and annotations

```console
kubectl -n k8s-learning-basics get pods --show-labels
kubectl -n k8s-learning-basics get pods -l app.kubernetes.io/part-of=core-components-project
kubectl -n k8s-learning-basics get deployment hello-web -o jsonpath='{.spec.selector.matchLabels}'
kubectl -n k8s-learning-basics get service hello-web -o jsonpath='{.spec.selector}'
kubectl -n k8s-learning-basics get deployment hello-web -o jsonpath='{.metadata.annotations}'
```

The Deployment and Service both select `app=hello-web`. Annotations describe the learning purpose but are not used for selection.

## 10. Create the DaemonSet

```console
kubectl apply -f manifests/40-daemonset.yaml
kubectl -n k8s-learning-basics rollout status daemonset/node-observer --timeout=120s
kubectl -n k8s-learning-basics get daemonset node-observer
kubectl -n k8s-learning-basics get pods -l app=node-observer -o wide
```

Expected result: normally there is one `node-observer` Pod on each eligible worker node. Compare the `NODE` column with `kubectl get nodes`.

Choose one observer Pod name and read its message:

```console
kubectl -n k8s-learning-basics logs PASTE_ONE_OBSERVER_POD_NAME_HERE --tail=3
```

## 11. Review the foundation resources

```console
kubectl -n k8s-learning-basics get all
kubectl -n k8s-learning-basics get configmap,secret,resourcequota
```

At this point the first ten lessons all connect to the same running project. The next steps extend that project for topics 11-20.

## 12. Run the catalog Job and CronJob

Create the one-time catalog importer:

```console
kubectl apply -f manifests/50-job.yaml
kubectl -n k8s-learning-basics wait --for=condition=complete job/catalog-import --timeout=120s
kubectl -n k8s-learning-basics logs job/catalog-import
```

Expected result: the log lists three imported books and finishes with `Catalog import completed`.

Create the scheduled report:

```console
kubectl apply -f manifests/51-cronjob.yaml
kubectl -n k8s-learning-basics get cronjob catalog-report
```

The schedule is every five minutes. Trigger the same template immediately so you do not have to wait:

```console
kubectl -n k8s-learning-basics delete job catalog-report-now --ignore-not-found
kubectl -n k8s-learning-basics create job --from=cronjob/catalog-report catalog-report-now
kubectl -n k8s-learning-basics wait --for=condition=complete job/catalog-report-now --timeout=120s
kubectl -n k8s-learning-basics logs job/catalog-report-now
```

Expected result: the log contains a UTC timestamp and a catalog count of three.

Inspect the ownership chain after a scheduled run:

```console
kubectl -n k8s-learning-basics get cronjob,jobs,pods
```

## 13. Observe the three probes

View the configured startup, readiness, and liveness checks:

```console
kubectl -n k8s-learning-basics describe deployment hello-web
kubectl -n k8s-learning-basics get pods -l app=hello-web
```

For a safe readiness demonstration, copy one current `hello-web` Pod name. Remove only its readiness file:

```console
kubectl -n k8s-learning-basics exec PASTE_WEB_POD_NAME_HERE -- rm /www/ready.html
kubectl -n k8s-learning-basics wait --for=condition=Ready=false pod/PASTE_WEB_POD_NAME_HERE --timeout=60s
kubectl -n k8s-learning-basics get pod PASTE_WEB_POD_NAME_HERE
kubectl -n k8s-learning-basics get endpointslice -l kubernetes.io/service-name=hello-web -o yaml
```

Expected result:

- The selected Pod changes from `1/1` ready to `0/1`.
- The container remains running because its separate liveness path still works.
- Its EndpointSlice entry can remain listed, but `conditions.ready` becomes `false` and normal Service routing excludes it after updates propagate. Find the entry by `targetRef.name`.

Restore the readiness file from the read-only ConfigMap template volume:

```console
kubectl -n k8s-learning-basics exec PASTE_WEB_POD_NAME_HERE -- cp /template/ready.html /www/ready.html
kubectl -n k8s-learning-basics get pod PASTE_WEB_POD_NAME_HERE --watch
```

When the Pod shows `1/1` ready, press `Ctrl+C`.

## 15. Inspect the init container

Choose one web Pod name:

```console
kubectl -n k8s-learning-basics get pods -l app=hello-web
```

Read the completed init-container log and status:

```console
kubectl -n k8s-learning-basics logs PASTE_WEB_POD_NAME_HERE -c prepare-page
kubectl -n k8s-learning-basics get pod PASTE_WEB_POD_NAME_HERE -o jsonpath='{.status.initContainerStatuses[0].state.terminated.reason}'
```

## 16. Inspect resource requests and limits

Show the web and init-container resource declarations:

```console
kubectl -n k8s-learning-basics get deployment hello-web -o jsonpath='{.spec.template.spec.containers[0].resources}'
```

## 17. Perform a rolling release and rollback

Confirm release 1.0:

```console
kubectl -n k8s-learning-basics exec deployment/hello-web -- wget -qO- http://hello-web
kubectl -n k8s-learning-basics rollout history deployment/hello-web
```

Apply release 2.0 and watch the rollout:

```console
kubectl apply -f manifests/releases/20-deployment-v2.yaml
kubectl -n k8s-learning-basics rollout status deployment/hello-web --timeout=120s
kubectl -n k8s-learning-basics get replicasets,pods -l app=hello-web --show-labels
kubectl -n k8s-learning-basics exec deployment/hello-web -- wget -qO- http://hello-web
```

Expected page: `Release 2.0`. The old ReplicaSet remains with zero desired Pods so its revision can support rollback.

Review history, then return to the previous Pod template:

```console
kubectl -n k8s-learning-basics rollout history deployment/hello-web
kubectl -n k8s-learning-basics rollout undo deployment/hello-web
kubectl -n k8s-learning-basics rollout status deployment/hello-web --timeout=120s
kubectl -n k8s-learning-basics exec deployment/hello-web -- wget -qO- http://hello-web
```

Expected page: `Release 1.0`.

## 18. Test Kubernetes DNS

Inspect the resolver configuration inside a web Pod:

```console
kubectl -n k8s-learning-basics exec deployment/hello-web -- cat /etc/resolv.conf
```

Resolve the Service through its short and namespace-qualified names:

```console
kubectl -n k8s-learning-basics exec deployment/hello-web -- nslookup hello-web
```

## 19. Add the optional stateful reading list

This step provisions persistent storage. First check the available StorageClasses:

```console
kubectl get storageclass
```

Continue only when an appropriate class is marked as the default. If none is default, ask the cluster administrator which class is safe, then add its exact name as `storageClassName` under `volumeClaimTemplates` before applying the StatefulSet.

Create the headless Service and StatefulSet:

```console
kubectl apply -f manifests/storage/60-headless-service.yaml
kubectl apply -f manifests/storage/61-statefulset.yaml
kubectl -n k8s-learning-basics rollout status statefulset/reading-list --timeout=180s
kubectl -n k8s-learning-basics get pods -l app=reading-list -o wide
kubectl -n k8s-learning-basics get persistentvolumeclaims
```

Expected result: Pods `reading-list-0` and `reading-list-1` are ready, each with its own bound claim.

Write a reading-list entry to replica 0:

```console
kubectl -n k8s-learning-basics exec reading-list-0 -- /bin/sh -c 'echo "favorite: Kubernetes Up and Running" >> /data/reading-list.txt'
kubectl -n k8s-learning-basics exec reading-list-0 -- cat /data/reading-list.txt
```

Resolve and reach the stable Pod name from the web application:

```console
kubectl -n k8s-learning-basics exec deployment/hello-web -- nslookup reading-list-0.reading-list
kubectl -n k8s-learning-basics exec deployment/hello-web -- wget -qO- http://reading-list-0.reading-list:8080/identity.txt
```

Replace replica 0 and prove its volume data remains:

```console
kubectl -n k8s-learning-basics delete pod reading-list-0
kubectl -n k8s-learning-basics rollout status statefulset/reading-list --timeout=180s
kubectl -n k8s-learning-basics exec reading-list-0 -- cat /data/reading-list.txt
```

Expected result: the replacement retains the same ordinal name and the same reading-list entry.

## 20. Add the optional ingress route

An Ingress object needs an already installed ingress controller. Check the cluster:

```console
kubectl get ingressclass
```

If no class exists, stop this step. Installing a controller changes shared cluster infrastructure and is outside this project.

The manifest omits `ingressClassName` and therefore expects a compatible default class. If your intended class is not the default, add this field under `spec` before applying:

```yaml
ingressClassName: PASTE_THE_INSTALLED_CLASS_NAME
```

After confirming the class and any platform cost with the cluster owner, apply the route:

```console
kubectl apply -f manifests/ingress/70-ingress.yaml
kubectl -n k8s-learning-basics get ingress bookshop
kubectl -n k8s-learning-basics describe ingress bookshop
```

Wait for the controller to report an address. Test it while supplying the required host header:

```console
curl.exe -H "Host: bookshop.example.com" http://PASTE_INGRESS_ADDRESS_HERE/
```

On Linux or macOS, use `curl` instead of `curl.exe`.

Expected page: `Tiny Bookshop`. The exact address and waiting time depend on the installed controller and platform.

## Troubleshooting

### A command returns `Forbidden`

Your Kubernetes identity does not have the required permission. Confirm the exact action:

```console
kubectl auth can-i create daemonsets -n k8s-learning-basics
kubectl auth can-i create jobs -n k8s-learning-basics
kubectl auth can-i create cronjobs -n k8s-learning-basics
kubectl auth can-i create statefulsets -n k8s-learning-basics
kubectl auth can-i create persistentvolumeclaims -n k8s-learning-basics
kubectl auth can-i create ingresses -n k8s-learning-basics
kubectl auth can-i list nodes
```

Ask the cluster administrator for the intended practice access. Do not bypass cluster policy.

### Pods show `ImagePullBackOff`

The nodes cannot obtain `busybox:1.36`. Inspect the events:

```console
kubectl -n k8s-learning-basics describe pod PASTE_POD_NAME_HERE
```

The cluster may require an approved registry mirror, credentials, or a different image reference.

### Pods remain `Pending`

```console
kubectl -n k8s-learning-basics get events --sort-by=.metadata.creationTimestamp
kubectl -n k8s-learning-basics describe pod PASTE_POD_NAME_HERE
kubectl -n k8s-learning-basics describe resourcequota learning-object-limits
```

Look for insufficient node resources, scheduling restrictions, or quota messages.

### The Service has no endpoints

```console
kubectl -n k8s-learning-basics get pods -l app=hello-web --show-labels
kubectl -n k8s-learning-basics get service hello-web -o yaml
kubectl -n k8s-learning-basics get endpointslice -l kubernetes.io/service-name=hello-web
```

The Service selector must match ready Pod labels.

### Port `8080` is already used

Choose another local port:

```console
kubectl -n k8s-learning-basics port-forward service/hello-web 9080:80
```

Then open `http://localhost:9080`.

### The init container does not complete

```console
kubectl -n k8s-learning-basics get pods -l app=hello-web
kubectl -n k8s-learning-basics logs PASTE_WEB_POD_NAME_HERE -c prepare-page
kubectl -n k8s-learning-basics describe pod PASTE_WEB_POD_NAME_HERE
```

Check the ConfigMap keys, volume mounts, file permissions, image pull, and init-container command before changing retry behaviour.

### The catalog Job fails

```console
kubectl -n k8s-learning-basics describe job catalog-import
kubectl -n k8s-learning-basics get pods -l job-name=catalog-import
kubectl -n k8s-learning-basics logs job/catalog-import
```

The example deliberately stops when `books.txt` is missing or empty. Check the ConfigMap and the Job's projected volume.

### The Deployment rollout stalls

```console
kubectl -n k8s-learning-basics rollout status deployment/hello-web --timeout=30s
kubectl -n k8s-learning-basics get replicasets,pods -l app=hello-web
kubectl -n k8s-learning-basics describe deployment hello-web
kubectl -n k8s-learning-basics get events --sort-by=.metadata.creationTimestamp
```

Do not force the old replicas down before understanding why the new replicas are unavailable. Use `kubectl rollout undo deployment/hello-web` when returning to the last working Pod template is the safe response.

### A PersistentVolumeClaim remains `Pending`

```console
kubectl get storageclass
kubectl -n k8s-learning-basics get persistentvolumeclaims
kubectl -n k8s-learning-basics describe persistentvolumeclaim data-reading-list-0
kubectl -n k8s-learning-basics describe resourcequota learning-object-limits
```

Typical causes are no default StorageClass, no working provisioner, topology restrictions, insufficient capacity, or quota rejection.

### The Ingress has no address or returns the controller default page

```console
kubectl get ingressclass
kubectl -n k8s-learning-basics describe ingress bookshop
kubectl -n k8s-learning-basics get service hello-web
```

Confirm that a controller watches the selected or default class, that the `Host: bookshop.example.com` header is present, and that the controller's own Service has a reachable address. Controller logs live in the namespace chosen by the cluster administrator.

## Cleanup

Read the current context again before cleanup:

```console
kubectl config current-context
```

If you completed the storage step, inspect the claims and StorageClass reclaim policy first:

```console
kubectl -n k8s-learning-basics get persistentvolumeclaims
kubectl get storageclass
```

Deleting the namespace deletes its PVC objects. A dynamically provisioned backing volume is commonly deleted when its PersistentVolume reclaim policy is `Delete`; a `Retain` policy leaves storage for administrator handling.

This command removes the dedicated learning namespace and all namespaced project resources:

```console
kubectl delete namespace k8s-learning-basics
```

Verify removal:

```console
kubectl get namespace k8s-learning-basics
```

`NotFound` means cleanup is complete.
